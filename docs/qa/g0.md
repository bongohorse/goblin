## Implemented behaviour

- Before Start, simulation and scoring are locked. After Start/Reset, the round is
  ready; its first valid interaction starts the timer. This is a G0 interim rule.
  Stable standing belongs to G3; the final stable-stand countdown belongs to G5.
- Without player input, settling never scores. Grabbing an already fallen Goblin
  does not retroactively award a fall. Direct-body interactions can cause a new
  fall bonus; projectile/contact-chain attribution remains G5 work.
- Fixed physics steps are 1/60 second, capped at three per render frame. Round
  time uses real active elapsed time, independently of dropped physics catch-up.
  Blur, visibility changes and Help pause time and discard accumulated delay.
- Pointer ownership, cancellation, lost capture, tool/camera changes and resize
  release dragging and clear tool forces. Forces do not accumulate each step.
- Reset restores the persistent Goblin and props, velocities, rotations, forces,
  objectives, score, timer and interaction state. Spawned projectiles are removed
  from Rapier, scene/mappings and their owned rendering resources.
- A nearer default camera, dynamic viewport height and short-landscape controls
  keep the basic scene usable. The final camera/UI design remains G7.
- The lockfile is checked in. CI and Pages use `npm ci` and run regression tests.

## Verification performed

Fresh `npm ci`, six Node regression tests and production build passed with Node
24.21.0. Tests cover spawn/reset score eligibility, pause/expiry, fixed stepping at
30/60/144 render FPS, bounded stalls and direct-action fall attribution.

Production browser checks used Chromium 153.0.8010.0 with software SwiftShader:
desktop 1280×720; touch-emulated landscape 744×360, DPR 3 capped to 1.5. They used
the `/goblin/` path, including relative assets. Browser/network errors and warnings
were empty.

- 60 seconds idle before Start on desktop and after Reset on touch emulation:
  score 0, no completed objectives, timer 60.
- Mouse grab, pointer cancel and touch action; Help pause/resume and blur/focus
  event handlers; 30 projectile attempts with a bounded body count.
- Twenty repeated resets: 22 bodies, 10 joints, no projectiles or stale grab.
- Portrait/landscape resize: canvas fits viewport, actions and toolbar do not
  overlap, effective mobile DPR stays capped.
- Screenshots were inspected; an initial control-overlap finding was fixed.
  A focused rerun checked the final layout and all interaction/reset scenarios.

Read-only diagnostics are opt-in with `?debug`; no test hooks mutate gameplay.
See [browser results](g0-browser-results.json), [desktop](g0-desktop.png) and
[touch landscape](g0-mobile.png). These show the current passive placeholder;
standing and model improvements are later gates. Missing emoji glyphs in this
headless Linux font setup are not evidence about Windows/Android font rendering.

## Baseline budget and limits

| Resource | Current G0 policy |
| --- | --- |
| Persistent bodies / joints | 22 / 10 |
| Projectiles | At most 24; oldest removed on overflow |
| Total bodies | At most 46 in the present scene |
| Physics catch-up | At most 3 steps per render frame |
| Effective DPR | At most 1.5 below 900 CSS pixels; otherwise 2 |
| Shadow map | One directional map, 1024×1024 |
| Hardware target | 60 FPS desktop/suitable mobile; stable 30 FPS weaker agreed profile |

The focused software run recorded about 116.6 ms median and 150 ms p95 frame
intervals, max measured CPU physics work about 7 ms/frame, 67 render calls and
11,608 rendered triangles in the recorded reset view. Software rendering and two
browser pages make this unsuitable for hardware FPS acceptance. It does **not**
meet or prove the target-device frame-rate budget. Lowering shadow resolution and
capping DPR reduce the pixel budget at the cost of shadow/image sharpness.

The existing approximately 4.88 MB uncompressed bundle warning remains; the
embedded Rapier Compat payload was not reworked in G0.

Suggested reference checks: Windows Edge/Chrome at 1280×720 and Android Chrome on
the user's Xiaomi Pad 6 in landscape. Device/browser versions must be recorded at
test time. Actual hardware performance, native touch/rotation and the newly
deployed commit still require verification. G0 must remain open until that evidence
and PR/CI acceptance are available; iOS coverage is also part of G8.
